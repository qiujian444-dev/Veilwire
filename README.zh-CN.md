# Veilwire（中文名：畅聊）

**[English](README.md) | 简体中文**

**Anonymous, end-to-end encrypted chat and calls. No account. No phone number. No central directory.**

一个基于**无标识队列 + 端到端加密 + 可自托管中继**的匿名通讯软件。
一期目标平台：Android。官方不运营任何公共服务，中继由用户/社区自建。

## 下载

**APK 不放在仓库里。** 一个包 26MB，历史版本累积起来会让 clone 变成几百 MB 且无法清理
（二进制一旦进了 git 历史就删不掉，只能重写历史）。发布都放在
[Releases](https://github.com/<owner>/veilwire/releases)。

| 文件 | 用途 |
|---|---|
| `veilwire-<版本>-arm64.apk` | 真机（Android 8.0+，arm64） |
| `veilwire-<版本>-x86_64.apk` | 模拟器（x86_64） |
| `SHA256SUMS` | 校验和 |
| `BUILD-INFO.txt` | 构建元数据（commit、工具链版本、签名证书） |

```bash
sha256sum -c SHA256SUMS
apksigner verify --print-certs veilwire-0.13.1-arm64.apk
```

发布签名是 `CN=Veilwire`（RSA 4096），证书 SHA-256：

```
4a991f0447b4ebef81b38c26ef937de86b632f3f3e9dd4e1b66e2d929e6eed1a
```

装之前核一次，对不上就别装：

```bash
apksigner verify --print-certs veilwire-0.13.1-arm64.apk | grep "SHA-256"
```

> ⚠️ 0.13.1 之前的测试包是调试密钥签的。换成正式密钥后**不能覆盖安装**，
> 要先卸载旧版（聊天记录在应用私有目录，卸载即丢；身份可用 12 词恢复短语重建）。
>
> 想更稳妥就别下载：按下面「如何自己编译并核对 APK」自己编一份。

维护者发版（构建 → 校验和 → 构建元数据 → 打 tag → 上传）：

```bash
bash scripts/release.sh 0.15.2            # 需先改好 versionName，且工作区干净
bash scripts/release.sh 0.13.1 --dry-run  # 只构建和打校验和，不碰 git/GitHub
```

## 为什么不是"抄 Session"

Session 的节点列表是硬编码公网 IP，封 IP 即全网瘫痪（俄罗斯已实证）。
国内没有可用节点，第一步握手就出境。照抄等于造一个连不上的软件。

我们的取舍：**「无中心」≠「无服务器」**。做到无账号、无中心目录、节点可被任何人替代；
接受"离线消息和音视频需要中继兜底"这个现实。

```bash
# 项目路径含中文会让链接器挂掉，复制到 ASCII 目录再构建

```

```bash
# 打洞/NAT 探测
```

### 当聊天工具用（两个终端，各有持久化身份）

```bash
relay serve --addr 127.0.0.1:8080 &

cli init --dir ./alice --name Alice
cli invite --dir ./alice --relay ws://127.0.0.1:8080     # 打印邀请码
cli init --dir ./bob --name Bob
cli invite --dir ./bob --relay ws://127.0.0.1:8080

cli add  --dir ./alice --invite <Bob 的邀请码>
cli add  --dir ./bob   --invite <Alice 的邀请码>

cli send --dir ./alice --to Bob --text "在吗"
cli recv --dir ./bob                                     # 前台收消息
```

身份、会话棘轮、去重表都落盘在 `--dir` 里，所以**每次命令都是独立进程，聊到一半关掉再打开还能继续**。
`cli recv` 只是前台监听，不是常驻服务——Android 端会用前台服务替代它。

> ⚠️ `cargo test` 只构建测试 harness，不会刷新 `target/debug/relay.exe` 本体。
> 改了 relay 源码后要显式 `cargo build`，否则跑的还是旧二进制。
> 网络不稳时加 `--offline`（依赖已在本地缓存）。

Android：用 Android Studio 打开 `android/stage0`，真机运行（模拟器测不出 Doze 和 ROM 杀后台）。

## 几条不能踩的线

| 约束 | 原因 |
|---|---|
| 长连接前台服务类型用 `remoteMessaging`，**禁用 `dataSync`** | Android 15 起 dataSync 24h 内只能用 6 小时，超时崩溃 |
| 通话时叠 `phoneCall\|microphone\|camera` 且**先拿权限再 startForeground** | 顺序反了抛 SecurityException |
| 不接 FCM / 厂商推送 | 推送服务商必然知道"设备此刻有消息"，与匿名定位冲突 |
| 重连用指数退避，**不要定时轮询** | Doze 下轮询最快 9 分钟一次，维护窗口可拉长到 6 小时 |
| 电池优化白名单是**必需项**，不是优化项 | Doze 期间系统暂停所有应用网络，前台服务不豁免 |
| 不复制 `libsession` / `session-android` 代码 | GPLv3 传染，只能读架构 |

### 语音消息（0.6.2）

输入框右边那个麦克风就是：**按住说话、松开发送、上滑取消**，不用先切"语音模式"。

- 单条最长 60 秒，到点自动停并发出去；短于 0.7 秒按误触丢弃，提示"说话时间太短"
  （`MediaRecorder` 在极短录制下 `stop()` 会抛异常并写出播不了的 mp4，这条线同时是安全线）。
- 录音时输入栏上方显示计时 + 实时电平柱。**电平柱不动就说明麦克风没在收音**——
  真机上这比"录完才发现是空的"强得多。
- 收到的语音只存在 App 私有目录（`files/inbox`），**不会自动落进「下载」**：
  语音是聊天正文，不是用户主动索要的文件，往下载目录丢一堆 `voice_*.m4a` 只是污染。
  也因此语音气泡上**没有**"保存到手机"菜单，点一下就是播放。
- 传输完全复用文件那条分块链路（24KB/块），没有第二套协议；AAC-LC 单声道 64kbps，
  60 秒约 480KB，20 块一批推完。播放在全局只有一个 `MediaPlayer`，点第二条会自动掐掉第一条。
- 通话进行中不给录音（麦克风被 WebRTC 占着，硬开只会录出静音）。

### 界面风格：手机端 IM 观感（0.7.0）

0.6.x 用的是 Material 3 默认调色板，我方气泡取 `primaryContainer` —— M3 默认是浅紫 `#EADDFF`，
聊天页里一条消息一个色块，一整屏都是紫的。这版换成一套 IM 皮肤（`android/.../Skin.kt`）：

- **灰底 `#EDEDED`**，顶栏/消息区/输入栏同色，只靠 0.5dp 细线分隔。
- **气泡**：我方绿 `#7FD44F`、对方白，**6dp 圆角**（M3 默认 12dp 显得"胖"）。
- **顶栏**：`‹` + **居中标题** + `···`（语音通话 / 视频通话 / 安全码收进菜单）。
  之前那两个描边按钮常驻，标题只能挤在左边。
- **输入栏**：白底 4dp 圆角输入框；**没字时是 `+`，有字才变绿"发送"** ——
  常驻发送按钮会让输入框永远少 60dp 宽度。
- **附件**：`+` 从底部推出面板，不再弹居中的 AlertDialog。
- **长按文字气泡**：复制 / 分享。之前长按**没有任何反应**，想复制个地址都做不到。
- **语音气泡**去掉了静态波形柱，改成喇叭 + 秒数，宽度随时长变化。
- 深色模式单独一套值（绿 `#3E9B39`、底 `#111111`），并补了 `values-night` 主题，
  否则系统导航栏那条会露白边。

刻意不照抄的三处：气泡绿不是微信的 `#95EC69`（同色系换一档，不搬别人的品牌色）；
没有头像（App 里没有头像数据）；没有"对方正在输入"（要改协议，不该混在 UI 改版里）。

### 图片与视频（0.6.3）

聊天页的 📎 里分成了「图片 / 视频 / 文件」三项，和微信一样先选类型再进相册。

- **图片先压再发**：长边 1600 px、JPEG 80。12MP 的照片 4 MB → 约 300 KB，
  否则 20 MB 的通道发五张就满。相册选择器是系统 Photo Picker，**不要任何存储权限**。
- **已经是合格 JPEG 的就直传**（长边 ≤ 1600、≤ 800 KB、EXIF 方向正常）：重编码只掉画质，
  体积还可能变大。实测 252 KB 的照片重压后成 272 KB，现在 md5 与相册原图完全一致。
- **气泡按原比例**（最大占屏宽 62%、屏高 42%），竖图不会被裁成方块；点一下在 App 内全屏，
  双指缩放、双击放大、点一下关闭。解码按屏幕尺寸采样，不会因为一张 48MP 的图把内存顶爆。
- **视频气泡显示首帧 + ▶ + 时长**，点开用 Media3/ExoPlayer 在 App 内播，进度条、暂停、拖动都有。
  刻意**不转码**：手机上写 MediaCodec 编码器成本远大于收益，所以 20 MB 上限靠"说清楚"——
  超限时直接告诉用户"这条 87.0 MB，先在相册裁到十几秒"。
- **图片/视频都不进「下载」**，和语音一致：内容属于聊天正文，自动写相册是隐私问题。
  要存的话长按气泡 → 保存到手机 / 另存为 / 分享。
- 传输上仍然只有一条协议：`kind=image` / `kind=video`，摘要里多 `w`/`h`/`dur`。
  对方没带这些字段（CLI、老版本客户端）时，接收端会在本地读一次文件补上。

### 紧急清除（0.11.0）

一个"对暗号清空双方"的强制销毁开关：**发起方验证、对端无感执行**。

- **暗号按身份派生**：`SHA-256("panic" + 排序后的双方身份公钥) → 6 位数字`。
  加上好友那一刻双方自动拥有同一个暗号——零配置（不存在"配错对不齐"的静默失效）、
  每对联系人唯一、不可预测、天然对称（双方都能发起）。设置页显示位置在聊天页
  `···` 菜单的「紧急清除」里。刻意**不做全局固定暗号**：全网皆知的暗号等于
  任何人都能触发你的清除弹窗。
- **触发**：把暗号作为**完整消息**打出并点发送 → 命中后**消息不发出**（不进对方
  设备、不进中继日志）→ 弹算术码（两位数加法）→ 答对执行。答错 3 次自动取消。
  `···` 菜单里也有显式入口，不用背暗号。
- **执行顺序是硬约束**：① 先发 `clear.exec` 加密消息给对方（此时密钥还在，能投递；
  对方离线就在中继排队，30 天内上线即清）→ ② 盲 ack 清空自己的中继队列
  （连接后对推来的每条消息直接 ack、**不解密**，中继零改动）→ ③ 删本机数据。
  对端收到 `clear.exec` **无确认直接执行同样的 ②③**——按设计，不需要对方确认。
- **清什么、留什么**：删聊天记录、收发文件副本、「下载/AnonChat/」的 MediaStore 条目、
  中继队列存量；**保留身份密钥、联系人和会话棘轮**——清完双方是无痕的空会话，
  无缝继续聊，不用重新互加。
- 三重防线：暗号（按身份派生、非常用短语）→ 算术码（防手滑）→ 明确的不可逆警告。
- 诚实边界：通知历史、系统剪贴板、中继运营者的服务器日志清不掉；
  对端长期离线，`clear.exec` 会在队列里等它上线（最多 30 天）；
  老版本客户端收到 `clear.exec` 不认识就忽略，不会崩也不会被清。

### 阅后即焚（0.10.0）

附件面板里多了「阅后即焚」一行：**关 / 30 秒 / 5 分钟**三档，**按条生效**——
选中后下一条消息（文字/图片/视频/文件/语音都算）带焚毁标记，发出去自动复位。

- 焚毁语义：**双端各自"首次展示"时开始倒计时**，到时本地删除，不留痕、不发网络请求
  （中继在消息被 ack 时就已经删干净，本来就无残留）。文件类的本机副本一起删。
- 计时起点落盘（`seenAt`）：App 被杀期间倒计时不会凭空重来，重启后接着算。
- 气泡旁显示剩余秒数，按秒跳；到期即消失。
- **系统通知脱敏**：焚毁消息的通知只显示"阅后即焚消息"，不显示内容——通知历史
  （Android 13+ 可回翻）是焚毁最大的洞，堵住了。顺手把附件消息通知里显示 JSON 串
  的老问题也修了。
- 诚实边界：**只保证 App 自己不留**。对方截图、录屏、相机翻拍防不住；没有已读回执，
  "看过"= 进入聊天页窗口（对方三天不打开，消息就躺三天才开始烧）。不做回执的原因：
  回执本身是元数据泄露（"他几点看了这条"），与匿名定位冲突。
- 兼容性：焚毁参数随密文走（文字在 body、文件在分块元数据），旧客户端收到当普通
  消息显示，不会崩——只是不焚（它不知道要烧）。

### 消息撤回（0.9.0）

发出 **10 分钟内**可以撤回自己发的消息（文字/文件/图片/视频），对方手机上同步消失，
原位置显示一条居中灰字（"你撤回了一条消息" / "对方撤回了一条消息"，微信同款）。

- 入口：文字气泡长按菜单里的「撤回」；文件/图片/视频气泡的菜单里也有一行
  「撤回」（只在窗口内出现）。撤回被拒（超时/对方没收到）会在输入栏上方提示。
- **跨设备定位靠 rid**：每条消息带一个发送方生成的引用 id——文字消息是加密载荷里
  的 `Payload.id`（协议 v1 就有，0.9.0 起透出到接收端），文件类消息直接用分块摘要
  里已有的 `fid`。两台设备各自的本地行号对不上，只有这个 id 两边一致。
- 撤回消息本身是 `kind=recall` 的普通加密消息（body 带 rid），不新开通道、
  中继无感知。旧版本客户端收到 recall 会静默忽略，不会崩。
- 撤掉的文件类消息会把本机副本（私有目录 + 已存下载的那份）一并删除，
  不留"已撤回"的尸体。
- 诚实说明边界：**撤回只是删双方聊天记录**。如果对方一直没上线，原消息还在
  中继队列里，他上线后先收到原消息、再收到撤回——顺序保证最终一致，但那一瞬间
  内容是到达过的。这是消息队列架构的物理限制，要做"彻底收不回"得改投递模型。
- 语音消息协议上支持撤回（rid 有了），但这版没给语音气泡加长按入口，下版补。
- 窗口只是客户端自律（10 分钟后菜单里不再出现「撤回」），不是安全边界。

### 发送失败可见与重发（0.8.0）

之前发送失败只在输入栏上方提示 4 秒，消息直接从列表里消失——用户根本不知道对方没收到。
现在失败的消息**留在列表里**：气泡旁边一个红色感叹号，会话列表预览带"（未发出）"。

- 点感叹号（或长按气泡 → 重发）直接重发，不弹确认；成功后感叹号消失，还是同一条消息，
  不产生新气泡。
- 失败状态跟着消息**落盘**（消息日志里一条 `f` 标记 + 重发成功后一条 `st` 回填记录），
  重启不会"假装发成功"。
- 只有文字消息有重发：文件/语音/图片发送失败根本不落记录（它们的来源可能已经不在，
  没有重发可谈），直接弹错误。
- 前置改造：消息有了**本地自增 id**（MsgStore 分配、append-only 日志落盘）。这是将来
  做删除/转发单条消息的地基——之前 `Msg` 连个能定位的身份都没有。

### 确定性头像（0.8.0）

App 里没有头像数据可传，但会话列表一排同色首字头像确实分不清人。
现在名字哈希（FNV-1a）→ 色相 + 首字：**同一个名字在任何一次启动、任何机型上都是同一个颜色**，
零存储、零网络。会话列表 42dp、聊天页顶栏 28dp。陌生人会话一眼能认出来（"陌"字 + 独立配色）。

### 解密失败日志定性（0.8.0）

2026-10-22 排查中继积压时，64 条 `MAC tag mismatch` 事后无法定性——日志里只有"没解开"三个字。
现在解密失败的告警带两样东西：

- **`mt`（0=预共享 1=普通）**：失败出在建立会话阶段还是已有会话阶段，处置完全不同；
- **逐会话指纹**：试解过哪些会话（对方公钥前 8 位 / 会话 id 前 8 位）、各败在哪一步
  （bad-mac / key-gap / padding / too-big-gap）。下次再出 MAC mismatch，一条日志就能看出
  是"换设备"（没有任何会话 MAC 过）还是"会话分叉"（部分会话 key-gap）。

### 中继 ack 修复（0.7.1）

0.7.0 及之前有一个埋了很久的缺陷：**中继只有在消息成功解密后才回 ack**。
后果是两头的：

- `ack()` 本身失败了（连接劣化、TLS 断开）只是 warn 一声就吞掉，消息在中继队列里**永远占着位置**
  （队列 TTL 约 30 天，期间对方每次重连都会把这批"已读"消息重新推一遍）。
- 解密报"密钥已消费"（**重复投递**的消息）也不 ack，于是这条消息成了永久钉子，
  对方每重连一次就重推一次、本地再解一次密——纯浪费流量和电。

0.7.1 的规则改成：**只有真正解不开（MAC 校验失败 = 篡改/损坏）才不 ack**，
其余情况——包括重复消息和 ack 发送失败（warn + 重试）——都会 ack。
另外给核心收发路径加了告警计数，异常会出现在日志里而不是无声无息。

验证方式：用中继的 `queues.log` 重放。清掉 84 条历史积压（全部是重复投递的文本消息，零 prekey）
后重连，put → recv → ack 全链路 **< 1 秒**，重复消息立刻 ack，伪造 MAC 的消息不 ack。

### 语音/视频通话

信令复用同一条加密消息队列，**中继不需要任何额外配置**，也看不出两端在通话。

```bash
# 信令端到端自测（假 SDP，验证两条身份之间的完整信令流）
cli calldemo --relay ws://127.0.0.1:8080

# 调试用：给某个联系人发一个 offer，把对方的来电界面叫起来
cli calloffer --dir ./alice --to Bob [--video]
```

媒体层是 WebRTC：P2P 直连优先，跨网段需要自建 TURN（见 `docs/中继部署指南.md`）。
TURN 只转发不解密，媒体流本身是 DTLS-SRTP 端到端加密的。

App 里在「设置 → 通话网络（STUN/TURN）」填 STUN/TURN；不填 TURN 时跨运营商大概率没有声音。

v0.6.0 起不用手抄：粘一行 `turn://用户名:密码@主机:端口` 点"解析并填入"就行，
再用"测试连通性"直接看结果——它会真的建一条 WebRTC 连接去收集候选，
拿到 `typ relay` 才显示 ✅，否则告诉你是 STUN 通而 TURN 没通（多半是密码或 3478/udp 被挡）。

每通电话结束会在聊天里留一条记录（`通话 01:23` / `未接来电` / `已拒接来电`），
未接来电不会无声无息地消失。

## 构建 Android APK

```bash
bash scripts/build-android.sh          # debug
bash scripts/build-android.sh release  # release，用本机 debug keystore 签名，可直接装机
```

产物按 ABI 拆分（WebRTC 的 libjingle 每个架构 11–12MB，不拆就是 44MB）：

| 文件 | 用途 | 大小 |
|---|---|---|
| `dist/anonchat-arm64-release.apk` | **真机安装**（release 构建，debug 签名可直接装） | 26MB |
| `build/outputs/apk/release/app-x86_64-release.apk` | 模拟器（x86_64），同样的 release 代码 | 25MB |
| `build/outputs/apk/debug/app-x86_64-debug.apk` | 模拟器调试（可 `run-as` 看数据） | 33MB |

构建环境（**版本必须对得上**，否则编出来的产物和别人对不齐）：

| 组件 | 版本 |
|---|---|
| JDK | 17 |
| Android SDK | platform 35 / build-tools 35.0.0 / NDK 27.0.12077973 |
| Gradle | 8.9 |
| Rust | 1.98.1，target `aarch64-linux-android`（**msvc 工具链**） |

脚本里的 `JAVA_HOME`、`ANDROID_HOME`、`GRADLE_BIN`、`BUILD_DIR` 都能用环境变量覆盖，
默认值是按开发机写的，换机器只改这几个。

构建里踩过的坑（脚本已经处理）：
1. **项目路径含中文**：Rust 链接会失败 → 复制到 ASCII 目录（`/c/anonchat-build/src`）再编；Gradle 需要 `android.overridePathCheck=true`。
2. **rustup target 装错工具链**：默认工具链是 gnu，构建用的是 msvc，要用 `--toolchain` 指定。
3. **crates.io / services.gradle.org 拉不动**：cargo 用中科大镜像，Gradle 用腾讯镜像 + 阿里云 Maven。
4. **单元测试在中文路径下跑不了**：Gradle 的 test worker 解析 classpath 失败（`ClassNotFoundException`，
   明明 class 就在 `build/tmp/kotlin-classes` 下）。`assemble` 不受影响，只有 `test` 任务中招。
   用 `bash scripts/test-android.sh`，它会复制到 ASCII 目录再跑（77 个用例，覆盖消息日志的读写/迁移/压缩/
   消息 id 与失败状态、撤回回放/窗口判定、焚毁档位/到期判定/seen 落盘、紧急清除暗号派生/匹配/算术码、
   语音时长与手势阈值、图片缩放/气泡尺寸/免压缩直传判定、头像哈希、TURN 链接解析）。

## 如何自己编译并核对 APK

**这一节为什么存在**：软件的全部安全性，最终落在"你手机里那份二进制是不是这份源码编出来的"。
官方不运营任何服务端，但 APK 是二进制分发——如果你只能信任我们发布的 APK，
加密只保护到"中继看不到"，保护不到"客户端里有没有后门"。

所以最稳的用法不是核对，而是**自己编、自己装**。下面是从零编出来，以及拿到别人的 APK 时怎么比对。

### 1. 编一份出来

前置依赖见上一节的版本表（JDK 17 / SDK 35 / NDK 27.0.12077973 / Gradle 8.9 / Rust 1.98.1 + Android target），
另外需要一个**纯 ASCII 的构建目录**（脚本会把源码复制过去编译，路径含中文时 Rust 链接会失败）。

```bash
git clone https://github.com/<你的账号>/veilwire.git
cd veilwire

export JAVA_HOME=/path/to/jdk-17
export ANDROID_HOME=/path/to/android-sdk
export GRADLE_BIN=/path/to/gradle-8.9/bin/gradle    # Windows 下是 gradle.bat

bash scripts/build-android.sh release
# → dist/anonchat-arm64-release.apk（真机）
# → dist/anonchat-x86_64-release.apk（模拟器）
```

Windows 上用 Git Bash 跑。编完直接 `adb install -r dist/anonchat-arm64-release.apk`。

### 2. 核对：先看元信息，再比代码

元信息（版本号、签名）：

```bash
aapt2 dump badging dist/anonchat-arm64-release.apk | head -3     # versionCode / versionName
apksigner verify --print-certs dist/anonchat-arm64-release.apk   # 证书指纹
```

> **签名怎么解读**：正式发布的包由 `CN=Veilwire` 的私钥签名，证书 SHA-256 公布在上面「下载」节。
> 所以这一步现在是**有意义**的：指纹对不上，就是伪造。
> 但你自己编出来的包签名必然不同（私钥只在我们手上），这不代表有问题——自己编的自己装就行。

真正有意义的是**比对代码本身**。APK 是个 zip，代码在 `classes*.dex`、`lib/<abi>/*.so`、
`resources.arsc`、`assets/` 里。**直接比整体 SHA-256 通常对不上**（签名块、zip 对齐与时间戳都会变），
所以要比条目，并排除 `META-INF/`（签名文件）：

```bash
python3 - <<'EOF'
import hashlib, zipfile

def entries(path):
    with zipfile.ZipFile(path) as z:
        return {
            i.filename: hashlib.sha256(z.read(i)).hexdigest()
            for i in z.infolist()
            if not i.filename.startswith("META-INF/") and not i.filename.endswith("/")
        }

a, b = entries("official.apk"), entries("mine.apk")
diff = [k for k in sorted(set(a) | set(b)) if a.get(k) != b.get(k)]
print(f"条目数：official={len(a)} mine={len(b)}")
print("不一致的条目：", diff if diff else "无")
EOF
```

逐条目全部一致 → 两份 APK 的代码相同，差异只在签名与打包时间戳。

### 3. 现在能核到什么程度（说清楚比含糊强）

| 对象 | 能不能跨机器比对 | 说明 |
|---|---|---|
| `classes*.dex` | 基本可以 | 同一套 JDK/AGP/Gradle 下 D8 输出稳定；版本不同可能产生差异 |
| `resources.arsc`、`assets/` | 基本可以 | 受 aapt2 版本影响 |
| `lib/<abi>/libanonchat.so` | **不行** | Rust 交叉编译产物，rustc 版本、NDK 版本、构建路径差一点 hash 就不同——这不是后门 |
| 整体 APK | 不行 | 签名块与 zip 时间戳天然不同 |

所以：**如果你编出来的 `classes.dex` 和我们发布的不一致，别装**（说明源码与二进制对不上）；
但 `.so` 不一致是正常的，不能用它判断真伪。

### 4. 还差什么（欢迎 PR）

- [x] 换成正式签名密钥（`CN=Veilwire`，RSA 4096），证书 SHA-256 已公布在「下载」节
- [ ] 可复现构建：`rust-toolchain.toml` 锁死 rustc、`--remap-path-prefix` 抹掉构建路径、
      固定 `SOURCE_DATE_EPOCH` 与 zip 时间戳，让 `.so` 也能逐字节复现
- [ ] release 流程附带构建元数据：源码 commit、工具链版本、逐条目 hash 清单，附在 Release 页

## 已知限制（这一版）

| 限制 | 影响 |
|---|---|
| 一次性密钥只能用一次 | 对方重装后旧邀请码失效，也解不开他新发来的消息，要重新互加 |
| 无 TURN 时跨运营商打不通 | 信令通、媒体不通，表现为"接通了但没声音"；配好 TURN 后先用设置页的"测试连通性"确认能拿到 relay 候选 |
| 通话中换网络 | 已支持自动重协商（`iceRestart`）+ 界面上的"重连"按钮 |
| 文件最大 20 MB，无断点续传 | 分块走消息通道（约 854 条），中断要重发 |
| 语音没有"保存到手机" | 只留 App 私有目录，卸载即丢（刻意的：语音属聊天正文，不进公共存储） |
| 图片/视频也不进「下载」 | 同上；要存就长按气泡 → 保存到手机 |
| 视频不转码、上限 20 MB | 约 720p 十几秒；更大的要先用相册裁剪。H.265/10bit 素材在部分机型上播不了 |
| 图片默认压缩到长边 1600 | 没有"发送原图"开关，细节要求高的话要等这个功能 |
| 语音最长 60 秒 | 超过要分多条发 |
| v0.6.1 之前发出的文件没留本地副本 | 那些气泡显示"不在本机"，只能让对方重发；新发的都有 |
| 聊天记录只在本机 | 换机 / 用恢复短语重建身份都带不走历史 |
| 界面上没有可自定义的头像 | 头像是名字哈希生成的（色相 + 首字），稳定但不可换；要上传/挑选头像得先有头像传输通道 |
| 消息只有"发送失败"一种状态 | 失败的留在列表里带红色感叹号、可重发；没有"发送中"转圈（本机写入和中继投递之间没有可汇报的中间态） |
| 不能删除 / 转发单条消息 | 撤回（0.9.0）有了；"仅自己删除不留痕"和"转发"还没做（id 定位手段已就绪） |
| 语音消息没有撤回入口 | 协议支持（rid 已透传），语音气泡还没加长按菜单，下版补 |
| 阅后即焚是 L1 语义 | "看过"= 进入聊天页窗口（无已读回执）；焚毁倒计时双端独立，只删 App 内的，防不住截图/录屏/通知外的旁路 |
| 无群聊、无多设备 | 明确不做/未做 |
