# 中继列表与收录规范 v0

> 对应可行性方案第 9 节的三级中继来源。本文档定义**社区层**列表的格式与收录规则，
> 以及客户端（App 内置快照 / 在线拉取）如何消费它。

## 1. 列表文件

- 文件名：`relays.json`
- 托管：社区仓库（GitHub 仓库 `anonchat/relay-list`，main 分支），raw 直链即引导地址
- 更新方式：PR，合并即生效（客户端下次拉取可见）
- 许可：CC0（数据无版权，随意镜像）

## 2. JSON 格式

```json
{
  "version": 1,
  "updated": "2026-10-20",
  "license": "CC0",
  "disclaimer": "此列表由社区收录，官方不运营、不背书、不保证任何中继的可用性与安全性。请只添加你信任的中继。",
  "relays": [
    {
      "url": "wss://relay.example.com",
      "region": "新加坡",
      "note": "由 @someone 运营，VPS 1核1G"
    }
  ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `version` | 是 | 格式版本，当前恒为 1 |
| `updated` | 否 | 最后更新日期，仅展示用 |
| `relays[].url` | 是 | `ws://` 或 `wss://` 完整地址。**官方建议 wss（443 端口 + TLS）** |
| `relays[].region` | 建议 | 大致地区/机房位置，用户按延迟和地区选择 |
| `relays[].note` | 否 | 运营者自述，最长 60 字。**不得含联系方式以外的推广** |

客户端行为（`RelayList.kt`）：

1. 启动引导页拉取 raw 直链（5 秒超时，失败静默）；
2. 成功 → 存本地缓存并展示（标注"官方列表（在线）"）；
3. 失败 → 用上次缓存（"缓存列表"）→ 内置快照（"内置列表"）；
4. 每条记录用 WS 握手测速（`relay_probe`，副作用为零：不建队列、不投递）；
5. **列表为空时绝不出错**，直接给"手输地址"入口——自定义层永远可用。

App 内置快照：`android/app/app/src/main/assets/relays.json`，发布时从社区仓库同步，
格式完全一致（当前为空列表——官方不放假条目，空就是空）。

## 3. 收录规则

**必须满足：**

1. 中继对公网可达，`relay_probe` 能完成 WS 握手；
2. 运营者留有可联系的渠道（note 里写清）；
3. 运营者明确知晓并声明：中继只做加密转发，但仍能看到"谁在什么时间连了哪个队列"这类元数据。

**会被拒绝：**

1. 备案主体为境内实体的 443 公开服务（合规定位：官方与列表都不收录境内公开运营节点，自建自用不受此限）；
2. note 含广告、挖矿、发币内容；
3. 匿名提交且无法联系。

**声明口径（写进 PR 模板）：**

> 我知晓：中继会接触连接元数据（IP、时间、队列 ID），但无法读取消息内容。
> 我承诺不记录、不出售这些元数据。此条目由我自行维护，可用性自负。

## 4. 客户端侧免责

App 的中继选择页固定展示：

> 中继只负责转发加密包裹，看不到消息内容。它由社区或你自己搭建，
> 官方不运营任何服务器。列表来自社区收录，不保证可用。

这句话是产品文案，不是可删的模板文本。
