# 安装与验收指南

> 面向：只负责装 APK 做验收的人。
> APK 位置：`dist/anonchat-0.13.1-arm64.apk`（真机用这个）
> 模拟器（x86_64）用 `dist/anonchat-x86_64-debug.apk`（可 `run-as` 看数据）

---

## 0. 这版能做什么

- 1v1 加密文本聊天（端到端加密，中继看不到内容）
- 无手机号、无注册，密钥即身份
- 后台常驻收消息（前台服务 + 电池白名单）
- 消息落盘，杀掉 App 再打开记录还在
- **语音 / 视频通话**（WebRTC 点对点，信令走同一条加密消息通道）
- **语音消息**（v0.6.2）：按住说话、松开发送、上滑取消，最长 60 秒；只存在 App 里，不进「下载」
- **图片与视频**（v0.6.3）：➕ 里选"图片/视频"，图片自动压到长边 1600，气泡直接显示缩略图，
  点一下**在 App 内**全屏看/播放（不跳出聊天去系统相册和播放器）
- **拍照直接发**（v0.13.0）：➕ 第一格"拍照"，调系统相机拍完即发，和相册选的图走同一条压缩链路。
  照片只落在 App 缓存、压完即删，**不进系统相册**（匿名聊天没必要在相册里留痕）
- **文件发送**（分块加密，单个文件上限 20 MB，收发双向、真实进度条）
- **文件保存到手机**（v0.6.1）：收到的文件自动落 `下载/AnonChat/`；点气泡可"打开/保存到手机/另存为/分享"，
  自己发出去的文件也留一份副本，不再"发完就找不着"
- 扫码 / 粘贴邀请码加好友（扫码页固定竖屏、左上角 ✕ 可随时退出），BIP39 12 词身份备份与恢复
- **回邀**：别人加了你、给你发消息，你点一下就能把他加为联系人并直接回复，不用他重新出码
- 未读角标、深色模式、聊天页消息实时刷新
- **聊天记录增量存储**：发一条只追加一行，不再重写整个历史文件；聊天页按页加载，几千条历史也不卡
- **安全码比对**（v0.6.0）：点会话标题显示 60 位数字，两端念一遍就知道有没有中间人
- **TURN 一键配置 + 连通性自检**（v0.6.0）：粘贴一行 `turn://…` 自动拆成地址/账号/密码，
  点"测试"直接告诉你这个 TURN 到底能不能用

**还不能做**：群聊、多设备同步。这两个明确不进当前版本。

## 1. 先跑一台中继（电脑上）

> **本项目不提供官方公共中继**：官方不运营任何节点，也不为任何中继的安全性背书。
> 联测需要你自己跑一台——一个进程同时提供 WS 中继与 TURN，方法见 `docs/中继部署指南.md` 3.3。
> 起好之后在 App 里填 `ws://<你的地址>:8080`，通话的 TURN 填
> `turn://<用户>:<密码>@<你的地址>:3478`。本地局域网中继的搭建方法见下文（离线/自建场景仍适用）。

手机要能连到中继，所以中继必须监听在局域网可访问的地址，**不能是 127.0.0.1**。

```bash
# 在电脑上（已编译好的二进制）
cd /c/anonchat-build/target/debug     # 或者用 cargo build -p relay 产物
./relay.exe serve --addr 0.0.0.0:8080 --data ./relay-data
```

查电脑的局域网 IP：

```bash
ipconfig | grep -A5 "无线局域网\|以太网" | grep IPv4
# 假设是 192.168.1.10
```

那么手机里要填的中继地址是：

```
ws://192.168.1.10:8080
```

> Windows 防火墙可能拦住 8080。第一次运行会弹窗，选"允许访问"。
> 也可以在"Windows Defender 防火墙 → 高级设置 → 入站规则"里放行 TCP 8080。

## 3. 首次启动流程

新版是三步引导：

1. **创建身份**：填昵称 → 点"创建身份"。
   密钥本地生成，不联网、不上报。也可以选"已有恢复短语？恢复身份"。
2. **抄写恢复短语**：12 个词网格展示，勾选"我已抄写"才能继续。
   > 这串词是身份的唯一备份。删 App、换手机都靠它找回身份（联系人要重新互加）。
   > 设置页"我的身份 → 查看恢复短语"随时能再看（旧版本创建的身份没有短语，会明确报错）。
3. **选择中继**：列表自动测速排序（每条显示地区和延迟），点选即用；
   列表拉不到或想用自己的中继时，在下方直接输入地址。
   > 中继只转发加密包裹，看不到内容；官方不运营服务器，列表来自社区收录、不保证可用
   > （格式见《中继列表与收录规范》）。

进入主页后：点"去授权"给电池白名单（小米/华为/OPPO/vivo 还要点"厂商自启动"）。
收消息服务**自动启动**，不需要手动点。

**扫码加好友**：双方当面互加时，A 点"我的邀请码"（生成后直接显示二维码），
B 点"添加联系人 → 扫二维码"，扫完点"添加"即可。

### 模拟器实测抓到并修掉的 bug

1. **底部输入栏被系统导航栏压住**（严重）
   Android 15 起强制边到边，Compose 不处理安全区 inset 的话，输入栏会画在导航栏下面，
   点"发送"实际点到系统导航键，App 直接退回桌面。已加 `safeDrawingPadding()` 修复。
   **这个问题编译期完全发现不了，只有跑起来才会暴露。**

2. **陌生人消息在 UI 上无处可看**
   未加为联系人的发送方，消息被存到"未知"键下，联系人列表里没有入口，用户永远看不到。
   已改为"陌生人 xxxxxxxx"会话，并在首页单列"未添加的联系人"。

3. **半开连接缓存后永远收不到消息**（严重，2026-10-21）
   连接空闲一段时间后 TCP 半开（无报错），缓存被无限复用，新消息永远收不到且无任何日志。
   已加心跳探测：收消息安静超时后发 Ping 等 Pong（5 秒），失败即丢弃缓存连接重连。
   回归测试 `stale_conn_recovery`（TCP 代理模拟半开）守着。

4. **聊天列表角标卡死**（2026-10-21）
   LazyColumn 的 items 内容 lambda 在列表 equals 相等时不重新执行，直接在 item 里读
   未读数会永远显示旧值。已改为未读数/最后一条消息随刷新一起作为状态更新。

5. **聊天页按系统返回键直接退出 App**（2026-10-21）
   Compose 自管导航但没有拦截系统返回。已加 BackHandler 回到聊天列表。

## 4.5 语音 / 视频通话

### 怎么发起

在聊天页顶栏点 **语音** 或 **视频**。只有已加为联系人的对象才能呼叫
（陌生人的会话密钥状态不确定，直接禁用了按钮）。

### 通话记录

每通电话结束都会在聊天里留一条居中灰字：

| 情况 | 记录内容 |
|---|---|
| 正常通话 | `通话 01:23` |
| 我方拒接 | `已拒接来电` |
| 对方拒接 | `对方拒接` |
| 振铃 45 秒无人接 | `无人接听`（主叫）/ `未接来电`（被叫） |
| 主叫在对方接听前取消 | `已取消` |

不留记录的话，未接来电在界面上完全没有痕迹，用户只会觉得"手机没响过"。

### 打不通电话时先改这里

设置页底部 → **通话网络（STUN / TURN）** → 展开：

- **STUN**：留空则用默认 `stun:stun.miwifi.com:3478`。同一 WiFi 下不需要改。
- **TURN**：跨运营商、跨网段必须填，否则媒体通道建不起来（信令是通的，只是没声音）。
  自建方法见 `中继部署指南.md` 的 coturn 一节。

**一键配置（v0.6.0）**：不用对着三个框抄。把一行链接粘进"粘贴 TURN 链接"，
点"解析并填入"，地址/用户名/密码自动分开填好。认得的写法：

```
turn://用户名:密码@1.2.3.4:3478          # 最常见
turns://用户名:密码@turn.example.com:443?transport=tcp
turn:1.2.3.4:3478                        # 没有账号密码时
1.2.3.4:3478                             # 裸地址也行，自动补 turn: 前缀
url=turn:1.2.3.4:3478?transport=udp      # 直接从 turnserver.conf 里复制的一行
```

**"测试连通性"按钮**：会真的建一个 WebRTC 连接去收集 ICE 候选，12 秒内给出结论：

| 结果 | 含义 |
|---|---|
| ✅ TURN 可用 | 拿到了 `typ relay` 候选，跨网段通话没问题 |
| ❌ TURN 没连上 | STUN 通但没有中继候选 → 地址/账号密码错，或 3478(udp) 被防火墙挡 |
| ⚠️ 只走了 STUN | 没填 TURN，或 TURN 空着。家用宽带大多能通，跨运营商仍会失败 |
| ⚠️ 只有内网候选 | 连 STUN 都没通，只能同一个 WiFi 打 |

> 为什么不能只 ping 端口：端口开着和"凭据能用、能分配中继地址"是两件事。
> 只有真收到 `typ relay` 候选，才算这条配置能打通跨网段通话。

改完点"保存设置"，**下一次通话生效**（已在通话中的不会切换）。

### 怎么接听

- App 在前台：直接弹出通话界面。
- App 在后台/锁屏：收到**全屏来电通知**，点"接听"进入通话界面。
- 服务必须处于"收到消息"状态，否则信令根本收不到。

### 模拟器**覆盖不到**的（必须真机）

- **真实音质与回声消除**：模拟器的虚拟麦克风没有声学回路，测不出 AEC 效果。
- **NAT 穿透**：模拟器和宿主机在同一台机器上，走的是 host candidate，等于没打洞。
- **摄像头**：模拟器是虚拟摄像头，画面是合成的。
- **不同网络（WiFi ↔ 流量）切换**：模拟器网络不切。

### 真机联调怎么少踩坑

1. **两端必须都能访问同一个中继**。手机连电脑上的中继时，中继要监听 `0.0.0.0`，
   手机填 `ws://<电脑内网IP>:8080`，Windows 防火墙要放行。
2. **跨运营商大概率连不通音频**。没有 TURN 时，媒体通道依赖 P2P 直连；
   同 WiFi 或同运营商能通，跨网段需要自建 TURN（`coturn`，见中继部署指南）。
3. **通话前会申请麦克风权限**。拒绝之后按钮会静默失败，检查系统设置。
4. **插耳机再测**。两台设备放一起会啸叫，那是扬声器—麦克风正反馈，不是软件 bug。

### 调试技巧

电脑上的 CLI 可以直接给手机发一个 offer，把来电界面叫起来，不用手点：

```bash
# 手机上生成邀请码，电脑上 add 进来，然后：
cli calloffer --dir ./hostpeer --to <手机上的名字>
# 观察手机回了什么（接听/拒接/挂断都会打到控制台）
cli callrecv --dir ./hostpeer --secs 30
```

`cli calloffer` 发的是**假 SDP**，所以手机端会立刻报"建立通话失败"，
但来电界面、通知、状态机、回包路径都是真的。用来验证 UI 和信令最省事。

## 4.6 两台手机互加好友

**A 手机：**
1. 点"生成邀请码" → 弹出邀请码 → 点"复制"
2. 通过任意渠道发给 B（当面念、微信发、二维码以后再做）

**B 手机：**
1. 把邀请码粘贴到"粘贴对方的邀请码"输入框
2. 点"添加联系人" → 出现"A 的昵称"

> ⚠️ **一个邀请码只能用一次**。因为我们没有中心服务器来分发一次性密钥，
> 只能把它塞进邀请码里。B 用掉之后，这个码就失效了，要给 C 加你，得重新生成。

**然后：**
- A 直接给 B 发消息即可（A 手里有 B 的队列）
- B 收到后**不需要**再让 A 出一次邀请码，见下面的"回邀"

### 回邀：陌生人消息怎么回（v0.4.0 起）

邀请码是单向的：A 拿了 B 的码，所以 A 能发给 B，而 B 手里没有 A 的任何路由信息。
以前 B 只能看着消息干瞪眼。现在每条消息都会在加密载荷里带上**回信线索**
（发送方的队列 ID、中继地址、显示名），B 点一下就能把 A 加进通讯录并直接回复。

**操作：**
1. 首页"未添加的联系人"里点进会话，底部会看到提示：
   "对方加了你，但还没在你的通讯录里。先加为联系人才能回复。"
2. 点 **加为联系人并回复** → 会话改名成对方的昵称，聊天记录跟着搬过去，输入栏恢复
3. 直接打字发送

![回邀提示](assets/ui-reply-banner.png)
![加完之后](assets/ui-reply-done.png)

**注意：**
- 对方必须先把消息发出来，你才有线索可加——不存在"凭空添加一个陌生人"
- 旧版本客户端发来的消息不带线索，这时提示会变成"暂时没办法回复"，让对方发一条新的即可
- 信任边界：只有加密层确认过的 `dh` 被当作身份，名字/队列/中继都是对方自报的，
  只用于路由，伪造这些字段顶多让你投错地方，不会让别人替对方读消息

## 4.7 文件发送与聊天记录（v0.5.0 起）

### 发文件

聊天页左下角的 📎 → 选文件 → 直接开传，输入框上方出现进度条
（已发/总量 + 百分比）。上限 **20 MB**。

![发送进度](assets/ui-file-sending.png)

对方那边会显示一条"正在接收 …（百分比 + MB）"的进度，收齐后变成文件气泡。

![收到 20MB](assets/ui-file-20mb.png)

### 文件到底存哪了、怎么拿出去（v0.6.1 起）

这是之前版本最容易被问住的地方，先说清楚：

| 位置 | 是什么 | 谁能看到 |
|---|---|---|
| `下载/AnonChat/` | **收到的文件自动存一份**（Android 10 及以上） | 文件管理器、相册、微信发文件都能选到 |
| App 私有 `files/inbox/` | 聊天自己用的副本，点气泡「打开」读的是这里 | 只有 App，卸载就没了 |
| App 私有 `files/sent/` | 自己发出去的文件留的副本 | 只有 App |

**点文件气泡会弹菜单**，四个动作：

- **打开** —— 交给系统找 App 打开（没装对应 App 会提示换「另存为」）
- **保存到手机** —— 落 `下载/AnonChat/`，Toast 直接告诉你完整路径；同名不覆盖，自动变 `xxx (1).bin`
- **另存为…** —— 系统文件选择器，自己挑位置（SD 卡、网盘都行）；Android 8/9 上「保存到手机」也走这条路
- **分享** —— 直接发给微信/QQ/邮件

气泡副标题会显示当前状态：`已存下载` / `点按打开` / `不在本机`。
标 `不在本机` 的是 **v0.6.1 之前发出去的消息** —— 那时发送方不保留副本，
只有让 ta 重发一次。收到的老文件不受影响，点开还能「保存到手机」补存一份。

![文件菜单](assets/ui-file-menu.png)

**我在模拟器上怎么验的（v0.5.0）：**

| 方向 | 做法 | 结果 |
|---|---|---|
| 电脑 → 手机 | `cli filesend` 发 20 MB 随机文件 | 手机落盘 20971520 字节，`md5` 与源文件**完全一致** |
| 手机 → 电脑 | 手机 📎 发同一个 20 MB | 电脑收到 854 块、无缺失，按 `idx` 拼回后 md5 一致 |

**v0.6.1 补验（保存到本机）：**

| 做了什么 | 结果 |
|---|---|
| CLI 发 27 B 的 `save_test.txt` 给手机 | 自动出现在 `下载/AnonChat/save_test.txt`，内容一致；气泡显示 `已存下载` |
| 手机发 `testfile.bin`（300 KB）给 CLI | 发送方气泡从"点不动"变成可点；`files/sent/` 有 307200 字节副本 |
| 电脑收下的 13 块拼回 | md5 `962084d7…`，与手机上源文件**完全一致**（边发边写副本没影响发送内容） |
| 同一文件连点两次「保存到手机」 | 第二个存成 `testfile (1).bin`，原文件没被覆盖 |
| CLI 再发一次 20 MB | 自动落到 `下载/AnonChat/big20.bin`，20971520 字节，md5 `24ff65b1…` 一致 |

也就是说收发两个方向的字节级正确性都验过了，不是"看起来传完了"。

**几个容易踩的点：**

- 20 MB 要拆成 854 条消息，传输中有十几二十秒是正常的（中继排队 + 逐条加密解密）
- 没有断点续传：中途退出/断网就得重发。大文件建议压缩后再发
- 中继如果开了严格限流（`--rate`），批推会被限流卡住，表现是"传一半失败"。
  客户端每批 40 块，是按"每连接 120 条/分钟"留了三倍余量算的

### 聊天记录怎么存的（改了什么）

以前每发一条消息都会把**整个历史文件重写一遍**。消息攒到几千条，发一条就要
几十毫秒的磁盘 IO，聊天越久越卡；更糟的是重写期间进程被杀会留下截断的 JSON，
整个历史一起丢。

现在改成**只追加**：

- `files/messages.log`，一行一条 JSON。发一条只写一行（实测：510 条历史、48 KB 的文件，
  收到一条新消息只增加 91 字节）
- 会话改名（回邀"加为联系人"）写一条 `mv` 记录，重启回放时历史照样落在新名字下
- 日志膨胀到"消息数 × 2 + 256"以上时自动压缩一次（重写临时文件再原子改名）
- **老版本升级上来的数据自动迁移**：启动时读旧的 `messages.json`，写成新日志，
  原文件改名成 `messages.json.migrated` 保留（万一新格式有问题，历史还在硬盘上）

聊天页也跟着改成**按页加载**：只把最近 60 条交给列表，往上滚到底再加载 60 条，
滚动位置会保持住；新消息只有在你正停在底部时才自动滚下去——翻历史时不会被顶走。

![往上翻历史](assets/ui-msg-paging.png)

> 这一层有 9 个 JVM 单元测试盯着（`bash scripts/test-android.sh`），覆盖：
> 追加与回放、改名回放、老格式迁移、**末尾半行截断**、压缩、区间读取边界。
> 其中"末尾半行"是实测抓到的真 bug：进程被杀留下半行且没有换行符，
> 后续追加会跟它粘成一行垃圾，导致**后续新消息也一起丢**——不只是丢最后一条。

## 4.8 安全码：确认"对面是谁"（v0.6.0）

**在哪**：打开会话 → 点标题里对方的名字 → 弹出"与 XXX 的安全码"。

**怎么用**：

1. 双方各自打开同一个会话的安全码；
2. 当面 / 打电话，一行一行念过去（3 行，每行 4 组，共 60 位）；
3. 两边完全一致 → 中间没有第三方。点"我已核对"，标题右侧出现 ✓。

**为什么需要**：邀请码是带外交换的（面对面扫码、口头念）。如果换设备，或者邀请码
在传递途中被替换，软件自己没法发现。安全码把双方的**身份公钥**（Ed25519，就是那串
43 字符 ID）排序后做 SHA-256，展开成 60 位数字——中间人若让两端各建一条独立会话，
两边算出的数必然不同，一念就露馅。

**几点要知道**：

- 安全码只跟**身份**有关，跟会话无关。重新扫码添加、用恢复短语重装都不会变。
  **它变了就说明对方换了身份**，值得警觉。
- "✓ 已核对"记的是"核对时的那串码"。码变了标记自动失效，标题上的 ✓ 会自己消失。
- 陌生人会话也能核对——只要收到过对方消息，公钥就已经拿到了。
- 它证明的是"这个身份没被换过"，不是"这条链路的每一跳都干净"。

![安全码](assets/ui-safety-code.png)

![核对后标题出现 ✓](assets/ui-safety-verified.png)

## 4.9 语音消息（v0.6.2）

**在哪**：聊天页输入框右边那个 🎤。

**怎么用**：

1. **按住**麦克风就开始录（不用等长按判定，按下瞬间就录，开头不会被吞掉）；
2. 说话时输入栏上方会出现计时 + 实时电平柱；
3. **松手就发出去**；不想发就**手指往上滑**（超过约 64dp 会变红提示"松开 取消"），松手即丢弃。

![按住说话](assets/ui-voice-recording.png)

**几条硬规则**：

| 规则 | 说明 |
|---|---|
| 单条最长 60 秒 | 到点自动停并发出去，和微信一致 |
| 短于 0.7 秒丢弃 | 提示"说话时间太短"。这条线不只是体验：`MediaRecorder` 在极短录制下 `stop()` 会抛异常，写出缺 moov box 的 mp4，播不了 |
| 语音**不进「下载」目录** | 语音是聊天正文，不是用户主动要的文件。它只存在 App 私有目录（`files/inbox`、`files/sent`），所以气泡上**没有**"保存到手机"菜单 |
| 点一下播放，再点暂停 | 全局只有一个播放器，点第二条会自动掐掉第一条；播放中显示的是**剩余**秒数 |
| 通话中不能录 | 麦克风被 WebRTC 占着，硬开只会录出一段静音 |

![语音气泡（含播放态）](assets/ui-voice-bubbles.png)

![深色模式下的语音气泡](assets/ui-voice-dark.png)

**传输上没引入第二条协议**：语音复用文件那套分块链路（24KB/块、批量推送、乱序写偏移、
`BitSet` 去重），消息类型换成 `kind=voice`，摘要里多一个 `dur`（毫秒）。
AAC-LC 单声道 64kbps，60 秒约 480KB，20 块一批就推完——比传一个文件还省事。

**我在模拟器上验证过什么**（x86_64，全部实测）：

| 项 | 结果 |
|---|---|
| 按住 6 秒松手 | 生成 `voice_20261022_021759.m4a` 50415 字节，聊天里出现 `▶ 波形 6"` 气泡 |
| 端到端一致性 | CLI 收 3 块、0 缺失，重组后 md5 `f9a4b6c2…` 与手机 `files/sent/` 里原件**完全相同** |
| 上滑取消 | 语音副本数不变（3 → 3），聊天里没有多出气泡 |
| 太短 | 点一下立刻松手 → 红字"说话时间太短"，4 秒后自动消失，不产生文件 |
| CLI → 手机（`--kind voice --dur 6000`） | 左侧灰色语音气泡 6"，`files/inbox` 落 50415 字节，点开能播、倒计时正常 |
| 语音不落公共存储 | `/sdcard/Download/AnonChat/` 里 `.m4a` 数量始终为 **0** |
| 冷启动后 | 4 条语音记录都在，点击仍能播放（`path` 指向的私有副本没被清） |
| 会话列表预览 | 显示 `🎤 语音 6"`，不是 JSON 原文 |
| 深色模式 | 我方/对方气泡与波形都清晰 |

**模拟器覆盖不到的（必须真机）**：

- **真实音质**。模拟器没有麦克风输入，录出来的是静音，只能证明"链路 + 容器格式可用"，
  听不出有没有杂音、爆音、AAC 编码器在特定 SoC 上的兼容性。
- **电平柱是否真的跟着说话跳**。模拟器上 `maxAmplitude` 恒定，看不出动态。
  真机上如果电平柱一直是一排矮点，先查麦克风权限和是否被别的 App 占着。
- 蓝牙耳机 / 有线耳机的录音路由（部分 ROM 会录到错误设备，表现为全是静音）。
- 锁屏/接电话打断时的收尾：代码里手势被系统中断会强制 `cancel`（不留文件），
  但只有真机能验证"打断后麦克风确实释放了"（状态栏录音指示消失）。

**出问题先看这里**：

| 现象 | 原因 / 处理 |
|---|---|
| 按了没反应 | 没给麦克风权限。第一次按会拉权限，允许后再按一次 |
| 松手后没声音、也没气泡 | 时长 < 0.7 秒（会提示）；或麦克风被别的 App 占着（会提示"录音失败"） |
| 气泡显示 ⚠ | 那条语音在本机没有副本了（换机、清过 App 数据），只能让对方重发 |
| 对方听不到 | 先确认自己点播放能听到。自己都听不到，是录音侧问题，不是传输 |

## 4.10 图片与视频（v0.6.3）

**在哪**：聊天页输入框左边那个 📎 → 弹窗里选「🖼 图片」「🎬 视频」「📄 文件」。

**图片**

1. 选图后先在本地压缩：长边 1600 px、JPEG 质量 80。一张 12MP 的手机照片（约 4 MB）压完通常 200–400 KB；
   已经是"合格 JPEG"的图（长边 ≤ 1600、体积 ≤ 800 KB、EXIF 方向正常）**原样直传**，不再重编码——
   重压只会掉画质，体积还可能变大（实测一张 252 KB 的照片重压后成了 272 KB）；
2. 气泡按**原比例**显示（最大占屏宽 62%、屏高 42%），竖图不会被裁成方块；
3. 点一下 → App 内全屏查看：双指缩放、双击放大/还原、点一下关闭；
4. 长按气泡 → 保存到手机 / 另存为 / 分享。

**视频**

1. 气泡显示**首帧缩略图 + ▶ + 时长**（读不到时长就不显示角标，不是 bug）；
2. 点一下 → App 内播放（Media3 ExoPlayer，有进度条、暂停、快退/快进，退出自动释放解码器）；
3. 长按气泡 → 保存到手机 / 另存为 / 分享。

![图片与视频气泡](assets/ui-media-bubbles.png)

*图片按原比例、视频带 ▶ 和时长角标（图中 0:10）*

![App 内全屏看图](assets/ui-media-viewer.png)

*点图片 → App 内全屏：双指缩放、双击放大、点一下关闭*

![App 内播放视频](assets/ui-media-player.png)

*点视频 → App 内播放：暂停、±5 秒、进度条，位置都在系统导航栏之上*

**几条硬规则**：

| 规则 | 说明 |
|---|---|
| 视频上限仍是 **20 MB** | 走的还是消息通道（约 854 块），20 MB 大致等于 720p 十几秒。**不做转码**——手机上写 MediaCodec 编码器成本太高，收益只有"能把大视频压小" |
| 超限会给具体数字 | 不再只说"超过上限"，而是"这条视频 87.0 MB，超过 20MB 的通道上限。先在相册里裁到十几秒再发" |
| 图片/视频**都不进「下载」** | 和语音一致：属于聊天正文，不是用户主动索要的文件。自动往相册/下载塞别人的图，是隐私问题 |
| 不发原图 | 只有本来就"合格"的 JPEG（≤ 1600 px、≤ 800 KB、方向正常）原样发；再大的先压。要无条件发原图得另做开关 |
| GIF 原样发，但只显示首帧 | 压成 JPEG 会把动画压没，所以 GIF 不压缩；App 内不解码动画（要看动图用长按菜单"打开"交给系统相册） |

**传输上同样没引入第二条协议**：图片/视频复用文件那套分块链路（24KB/块、批量推送、乱序写偏移），
只是 `kind` 换成 `image` / `video`，摘要里多 `w` / `h` / `dur`。
接收端如果发现对方没带这些字段（CLI、老版本客户端），会**在本地读一次文件补上**，
否则竖图会被按 4:3 裁掉。

**我在模拟器上验证过什么**（x86_64，全部实测）：

| 项 | 结果 |
|---|---|
| 发一张 1080×2340 截图 | 压缩为 738×1600 / 55 KB，CLI 收 3 块 0 缺失，重组后 md5 与手机 `files/sent/` 一致 |
| 气泡比例 | 框 164.9×357.4 dp（= 源图 0.461 比例），竖图未被裁切 |
| 发一张 252 KB / 1200×1600 的合规 JPEG | **原样直传**：`files/sent` 里 252,048 字节，md5 与相册原图完全一致（改之前会被重压成 272,654 字节） |
| 点开图片 | App 内全屏，顶部有"双指缩放 · 双击放大 · 点一下关闭"和"关闭"，浅色图上也能看清 |
| 发 10 秒标准视频（640×360） | 41 块全部到达，`dur=10000`，气泡显示 `▶ 0:10` |
| 点开视频 | App 内播放，进度条/暂停正常，进度条已避开系统导航栏 |
| CLI → 手机（`--kind image`，不带宽高） | 落 `files/inbox`，本地补读出 1080×2340，气泡比例正确 |
| 不落公共存储 | `/sdcard/Download/AnonChat/` 里 `.jpg` / `.mp4` 数量始终为 **0** |
| 会话列表预览 | 显示 `[图片]` / `[视频]`，不是 JSON 原文 |

**模拟器覆盖不到的（必须真机）**：

- **HEIC/HEIF**（iPhone 传来的图、部分安卓默认格式）：API 28+ 能解，26/27 会提示"这张图解不开"。
- 超大图（1 亿像素以上）会主动拒绝，但阈值是否合适要看真机内存。
- 视频编码兼容性：H.265 / 10bit / 高码率素材在部分机型上解不出来（ExoPlayer 会黑屏但不崩）。
- 相册里选原图的耗时（模拟器上是空的相册，几毫秒就返回）。

**出问题先看这里**：

| 现象 | 原因 / 处理 |
|---|---|
| 视频选不了，提示超过 20MB | 通道上限，不是 bug。用相册自带的裁剪/压缩先处理 |
| 图片气泡显示"⚠ 不在本机" | 那条图在本机没副本了（换机、清过 App 数据），只能让对方重发 |
| 视频黑屏但有声音 | 编码不受支持（H.265/10bit 常见）。让对方转成 H.264 再发 |
| 图片发出去变模糊 | 默认压到长边 1600。要清晰原图得等"发送原图"功能 |

## 4.11 界面风格：手机端 IM 观感（v0.7.0）

**为什么改**：0.6.x 用的是 Material 3 的默认调色板，我方气泡取 `primaryContainer`，
M3 默认是浅紫 `#EADDFF` —— 聊天页里一条消息就是一个色块，一整屏都是紫的；
再加上"返回"是文字按钮、发送键常驻、附件是居中弹窗，用起来不像任何一个 IM。

**改了什么**

| 部位 | 之前 | 现在 |
|---|---|---|
| 底色 | 近白 `#FFFBFE` | 消息区 / 顶栏 / 输入栏统一 `#EDEDED`，靠 0.5dp 细线分隔 |
| 气泡 | 浅紫底 + 12dp 圆角 | 我方 `#7FD44F` 绿、对方白，**6dp 圆角**，16sp / 23sp 行高 |
| 顶栏 | "返回"文字 + 左对齐标题 + 两个描边按钮 | `‹` 图标 + **居中**标题 + `···`（语音/视频通话、安全码收进菜单） |
| 输入栏 | 描边输入框 + 常驻"发送" | 灰底 + 白底 4dp 圆角输入框；**没字时是 `+`，有字才变绿"发送"** |
| 附件 | 居中 AlertDialog 三行文字 | 从底部推上来的面板（图片 / 视频 / 文件 大图标方块） |
| 长按 | 文字气泡**没有任何反应** | 复制 / 分享 |
| 语音气泡 | 一排静态波形柱 + 秒数 | 喇叭 + 秒数，宽度随时长变化 |

## 4.12 消息确认（ack）与重复消息（v0.7.1）

这一节不是功能，是修一个**会越积越脏**的底层问题。普通用户感觉不到它，
但只要中继队列脏了，每次重连都会白推几十条几十 KB 的密文、日志刷一堆"无法解密"。

### 问题是怎么发现的

做媒体验证时开着的 CLI 接收端跑了 1 小时 42 分，收下 137 条消息，其中 **83 条解不开**：

| 报错 | 条数 |
|---|---|
| `message key can't be created, message index: 0…18` | 19 |
| `MAC tag mismatch` | 64 |

重放中继的 `queues.log` 才看清：Iris 队列积压 **84 条未 ack、共 847 KB，全部是普通消息**
（`mt=1`），**一条 prekey 都没有**。这个细节直接排除了"会话没建起来/身份被重置"。

再换个新连接重投这 84 条：**65 条立刻解开并 ack**，19 条报"密钥已用过"。
所以加密、协议、ack 通道本身都是好的——坏的是**ack 的可观测性**和**重复消息的确认策略**。

### 两个根因

1. **ack 失败被吞掉**：`client/src/lib.rs` 里写的是 `let _ = conn.ack(...)`，
   CLI 侧也一样。那个跑了 1h42m 的连接后期已经劣化（最后报"等待中继响应超时"），
   ack 全程静默失败 —— 65 条处理过的消息一条都没从队列里删掉。
2. **重复消息永远 ack 不掉**：ack 只在解密成功后调用。Olm 对**已经消费过**的消息会明确报
   `MissingMessageKey`，这本来属于"已处理过、可以确认删除"，却走不到 ack 分支，
   于是每条约 60 KB 的密文永久留在队列里，每次重连都要重投一遍。队列 TTL 是 30 天，
   等于连续一个月每次重连都白推 847 KB、刷 19 条错误。

### 改了什么

| 项 | 之前 | 现在 |
|---|---|---|
| ack 失败 | `let _ = ...` 完全静默 | 失败告警 + 重试一次；两次都失败计入 `ack_failed` |
| 解密失败分类 | 一律一个字符串 | 五类：`duplicate` / `poison` / `bad-mac` / `no-session` / `unknown` |
| ack 策略 | 只有解密成功才 ack | `duplicate`、`poison` 也 ack；其余不 ack |
| 首条 prekey 重投 | 建会话失败 → 报错不 ack | 已有该发送方会话 → 判 `duplicate` 并 ack |
| 日志 | 一句"无法解密来自 X" | 带 `[分类]` + **有没有删** + 同类累计第几条 |

### 为什么 bad-mac 不 ack

ack 的语义就是"从中继删掉"。删掉就真丢了，所以只对两种确定的情况删：

- `duplicate`（Olm 密钥已消费 / 载荷 id 命中去重表）→ 之前处理过，删了没有信息损失；
- `poison`（base64 坏了、载荷结构坏了、版本不支持）→ 永远解不开，留着只会无限重投。

`bad-mac`（MAC 不匹配）、`no-session`（没有可用会话）、`unknown` 一律**不删**：
这三类有可能是真丢了消息，留在队列里还能人工对账（30 天窗口）。
代价是这类消息会持续重投 —— 这是刻意选的，宁可多推几遍也不静默删消息。

### 模拟器 + 中继实测（都是真实端到端，不是单测）

| 场景 | 怎么造 | 结果 |
|---|---|---|
| App 收到重复消息 | 把 App 已收过的那条密文**换一个新 id** 重投（同 id 会被中继幂等挡掉） | 12 秒内完成 `put → 解密失败 → ack`；日志 `[duplicate] 已确认并从中继队列删除…同类累计 1 条` |
| CLI 收到重复消息 | 同上，投到 CLI 的队列 | 输出 `无法解密 [duplicate] 已确认并删除（重复或结构损坏）`，中继日志出现该 id 的 ack |
| MAC 不符不能删 | 改坏密文中间一个字符，并确保这个 index **还没被消费过** | 日志 `[bad-mac] 保留在队列中（未确认）`，中继日志里**没有** ack，消息留在队列 |
| 修完链路是否正常 | 正常发一条 | `put → ack` 完整闭环，消息正常显示 |
| 单元测试 | `cargo test --workspace` | Rust 全绿（secure 40 个，新增 6 个分类用例）；Kotlin 43 个 |

> 为什么"改坏一条重投的密文"会报 duplicate 而不是 bad-mac：Olm 解密是**先按 index 取消息密钥、
> 之后才验 MAC**。index 已被消费过的消息，在取密钥那一步就返回 `MissingMessageKey` 了，
> 根本走不到 MAC 校验。所以要测 bad-mac 必须造一条 index 未消费的坏密文。

### 出问题时怎么查

- App 侧：`adb logcat | grep 核心告警`，每条形如
  `无法解密来自 480字节/类型1 的消息 [bad-mac] 保留在队列中（未确认），同类累计 1 条: …`。
  `[duplicate]` 涨说明在自愈（正常），`[bad-mac]` / `[no-session]` 涨才是真问题。
- 中继侧：`emu-relay-data/queues.log` 是 append-only 的 `put` / `ack` / `new` 记录，
  重放出"当前未 ack 列表"就能看出谁卡住了。
- 清理脏队列**不要改文件**（中继内存里的队列不会跟着变）：用 `relay_ack.js` 走协议 ack。

### 5.1.2 收消息健壮性（2026-10-20 深夜修复，需真机复验）

模拟器实测抓到一个静默卡死：**身份刚创建、还没生成第一个邀请码的窗口里**，
收消息服务每轮报"还没有自己的队列"；生成邀请码后循环可能永久静默（服务活着但再也不收）。

根因（两个叠加的确定性缺陷，均已修）：

1. `Conn::connect` 的 WebSocket 握手**没有任何超时**——遇到半开连接（adb reverse、NAT 老化）
   `connect_async` 永久挂起，`recv_once` 永不返回，Kotlin 循环卡死在 `withContext`。
2. `recv_msg` 的超时是**每帧重置 30 秒**而不是总时长上限——只要对端以小于 30s 的间隔持续
   发帧（补投、错误帧）就永远等不到超时。

修复：连接硬超时 10 秒；收消息改为 deadline 语义（总等待 30s 硬上限）；Kotlin 循环的
消息处理段（通知/信令/状态发布）补上 try/catch，任何异常不再杀死整个循环。

验证状态：Rust 单测 23 项全绿；CLI 经真实中继双向收发回归通过（与 App 共用同一 client 代码）。
**App 端的复验因模拟器 guest 被宿主机 CPU 配额冻结而未完成，装机后请按 5.1.1 第 6 项 +
上表第 6 项实测。**

### 5.2 后台保活（这是最关键的一项）

这是判断这版能不能"当日常 IM 用"的唯一标准。

**A 组（授权白名单）**

1. 确认 App 内显示"已授予电池白名单"
2. 点"开始收消息"，确认通知栏有常驻通知
3. **锁屏，不充电，静置 24 小时**（别碰它，移动或亮屏会退出 Doze，等于作弊）
4. 24 小时内，让另一台手机每隔几小时发一条消息
5. 记录：收到几条 / 延迟多久

**B 组（不授权白名单）**：第 1 步跳过，其余相同。这组用来知道最坏情况。

**数据导出**：App 每 5 分钟往 CSV 写一行

```
Android/data/io.anonchat.app/files/stage0-stats.csv
```

列含义：`时间, 在线累计秒, 重连次数, 收到条数, 是否授白名单`

**判定**：
- A 组 24 小时内重连次数 ≤ 2，消息延迟 < 60 秒 → 通过
- 否则先看是不是没加厂商自启动（小米的"省电策略"是独立于系统白名单的第二道锁）

## 6. 常见问题

**收不到消息**
1. 中继地址对不对？（手机浏览器打开 `http://192.168.1.10:8080` 应该有响应或至少不是超时）
2. 两台手机和电脑在同一个 Wi-Fi？
3. 电脑防火墙放行了吗？
4. 通知栏有没有常驻通知？没有说明服务没起来。

**提示"邀请码已失效 / 建立会话失败"**
对方那个邀请码已经被用过了。让对方重新生成一个。

**点了发送，对方没收到，也没报错**
中继收到了但对方不在线，消息在队列里存着（TTL 30 天），对方下次上线会补投。

**收到的文件存哪了？**
`下载/AnonChat/`（用系统的「文件管理」或「下载」App 能看到）。
点聊天里的文件气泡还有「另存为…」可以自己挑位置。
Android 8/9 上不自动存（写公共目录要全盘存储权限），点气泡「保存到手机」走系统选择器。

**换手机了，记录能迁吗？**
不能。这是无中心设计的代价：没有服务器帮你备份，也没有"找回账号"。
以后的版本会给恢复短语（BIP39 12 词），现在这版还没接。

## 7. 这版已知限制（别当 bug 报）

| 限制 | 原因 |
|---|---|
| 一个邀请码只能用一次 | 无中心分发一次性密钥的固有代价 |

| 文件最大 20 MB | 分块走消息通道，20 MB ≈ 854 条消息，中继要排队；没有断点续传，中断要重发。更大的文件得等独立传输层 |
| 语音最长 60 秒，且不落「下载」 | 到点自动发；语音属聊天正文，只留 App 私有目录（卸载即丢）。想导出只能靠对方的播放/录屏，暂无"另存" |
| v0.6.1 之前发出去的文件没有本地副本 | 旧版本发送方只记了一条消息、没留文件，所以那些气泡显示"不在本机"。新发的都有；收到的老文件点气泡仍可"保存到手机" |
| Android 8/9 收到文件不自动进「下载」 | 写公共下载目录需要 WRITE_EXTERNAL_STORAGE，为一个保存功能要全盘权限不划算，改为点气泡走系统选择器另存 |
| 聊天记录只在本机 | 换机/恢复身份都带不走历史，这是无中心设计的代价 |
| 恢复短语只恢复身份本身 | 联系人/会话/聊天记录不随短语走，恢复后要重新互加 |
| 旧版本创建的身份没有恢复短语 | 短语身份派生是后加的；重新创建身份才有 |
| 不支持群聊 / 多设备 | 明确不做 |
| 息屏后可能有延迟 | 取决于是否给了电池白名单和厂商自启动 |
| 32 位老机器装不上 | APK 只打 arm64-v8a 和 x86_64 |
| 中继列表可能为空 | 社区收录是冷启动，手输地址永远可用 |
